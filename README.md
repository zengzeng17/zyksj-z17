# zyksj-z17 · 向外看传播研究

把一次产品发布、营销活动或争议事件，整理为结论清晰、来源可查的传播复盘。

## 它解决什么问题

报告围绕一条主线，用 **意图、设计、执行** 三层解释：对方想争取谁、主推什么、与谁竞争；传播核心信息（KM）如何配合demo、素材和渠道；实际反馈与原本希望促成的变化有哪些偏差。

效果研究覆盖声量与持续性、信息提及、渠道数量与分工、节奏、传播路径、反馈与行动。验证融入各层判断和可展开证据，保留反证、未知与数据口径，不把评论当总体民意，也不把曝光当商业转化。

## 安装

这是供 Codex 使用的技能目录，主入口为 `SKILL.md`。

1. 下载本仓库 ZIP 并解压，将文件夹命名为 `zyksj-z17`。
2. 将整个文件夹放入 `~/.codex/skills/`。
3. 在 Codex 中使用 `$zyksj-z17` 发起研究。

初始化、校验与渲染脚本需要 Python 3.9 或更新版本，仅使用标准库。资料检索、浏览器和平台数据工具由使用者自己的环境提供。

## 使用示例

```text
$zyksj-z17 分析这个产品本次发布的传播效果。
重点了解用户反馈、海外传播路径，以及哪些执行环节偏离了原本意图。
正式调用计费接口前先给我框架，等我确认。
```

也可以直接给出事件、时间范围和重点问题，授权后完成研究与HTML报告。默认重点渠道为 X、Hacker News、Reddit、微信公众号、视频号、小红书；按实际可用工具和用户要求调整。

## 项目辅助脚本

```bash
python3 scripts/init_project.py --output /path/to/new-research-project
# 进入生成的项目后：
python3 scripts/research.py init YYYY-MM-DD-event --title '事件名称'
python3 scripts/research.py validate cases/YYYY-MM-DD-event
python3 scripts/research.py build cases/YYYY-MM-DD-event --draft
```

辅助脚本负责建案、结构检查和渲染，不自动产生事实，不自带一键全平台采集器。报告需按技能要求补充真实来源、样本、分析和人工核验，完成QA后再正式构建。

## 数据授权与密钥

本仓库不提供或包含API Key、Cookie、账号Token、私人配置、原始采集数据、个人案例报告或网站仓库。TikHub、红狐等仅是可选访问路径，不是必需依赖；参考接口可能变化，使用前核对当前官方文档。

需要数据服务时，使用者自行配置密钥和授权。密钥应保存在环境变量或研究项目之外的私密文件中，不写进本仓库、报告、公开包、日志或聊天。仅使用明确授权的预算，不自动充值或购买。

提交前可以运行：

```bash
python3 scripts/check_secrets.py .
```

检查器只输出可疑文件位置和规则名称，不回显命中值。它用于辅助检查，不能保证识别所有形式的凭据；公开前仍应审阅完整待发布文件清单。
